Technology

Technology Stack & Why

Playwright

Auto-wait mechanism eliminates flaky tests. Built-in network interception, trace viewer, and multi-browser from one API. No external driver binaries needed.

TypeScript

Compile-time error detection catches bugs before tests run. IDE autocomplete shows available page object methods. Interfaces document data shapes.

axe-core

Industry-standard accessibility engine. Scans for WCAG 2.0 A/AA violations with actionable remediation guidance.

dotenv

Environment-specific configuration without code changes. Same framework targets dev, staging, or production via BASE_URL.

Architecture

Framework Structure

playwright-capstone/ config/ env.config.ts Environment settings fixtures/ test-fixtures.ts DI + ad blocking pages/ base.page.ts Shared methods home.page.ts + 7 more pages tests/ auth.spec.ts + 7 more suites testdata/ users.json + 3 data files utils/ data-reader.ts + 2 utilities playwright.config.ts Runner config

Separation of Concerns

  • pages/ — HOW to interact with UI elements
  • tests/ — WHAT business logic to verify
  • testdata/ — WITH WHAT values to test
  • fixtures/ — HOW to set up each test
  • utils/ — SHARED tools across the framework

A locator changes? Update one page object.
New test data? Edit one JSON file.
New page? Add one class + one fixture line.

Design Pattern

Page Object Model

Without POM

// Locators scattered in every test
await page.locator('[data-qa="login-email"]')
  .fill(email);
await page.locator('[data-qa="login-password"]')
  .fill(password);
await page.locator('[data-qa="login-button"]')
  .click();
// Repeated in every test that logs in

With POM

// Clean, readable, maintainable
await loginPage.login(email, password);

// Locators defined ONCE in LoginPage class
// If UI changes, fix ONE file
// All 84 tests stay clean

Framework Feature

Custom Fixtures

What Fixtures Do

// Tests declare dependencies
test('checkout', async ({
  homePage,
  loginPage,
  cartPage,
  checkoutPage,
}) => {
  // All page objects injected
  // automatically constructed
  // ads already blocked
});

Why This Matters

  • Dependency Injection — tests don't construct objects
  • Ad Blocking — configured once, applied everywhere
  • Lazy Loading — only requested page objects are created
  • Test Isolation — fresh browser context per test

Ad Blocking Strategy

Google Ads on the site overlay clickable elements. We abort ad network requests via page.route() at the fixture level.

Data-Driven Testing

Test Data (products.json)

{
  "searchTerms": [
    "top",
    "tshirt",
    "dress",
    "jeans",
    "saree"
  ]
}

Test Code

for (const term of data.searchTerms) {
  test(`Search "${term}"`, async ({
    productsPage
  }) => {
    await productsPage.searchProduct(term);
    await productsPage.verifySearchResults();
  });
}
// 1 code block = 5 tests
// Add a term = add 0 lines of code

Key benefit: QA engineers can add test cases by editing JSON, no TypeScript knowledge required. Test logic and test data are completely separated.

Modern Practices

Network Mocking, Accessibility & Visual Regression

Network Interception

Intercept and log HTTP requests, mock API responses, block resources (images), simulate slow networks, validate response status codes.

await page.route('**/*.png',
  route => route.abort()
);

Accessibility (axe-core)

Scans pages for WCAG 2.0 Level A/AA violations. Filters for critical and serious impact. Reports rule ID, description, and help URL.

new AxeBuilder({ page })
  .withTags(['wcag2a'])
  .analyze();

Visual Regression

Full-page screenshots compared against stored baselines. 5% pixel threshold accounts for rendering differences. Baselines stored in git.

await expect(page)
  .toHaveScreenshot(
    'home.png'
  );

Debugging

Trace Viewer & Debugging Tools

4 Debugging Methods

  • HTML Report — Screenshots, test steps, trace links
  • Trace Viewer — Step-by-step timeline with DOM snapshots, network logs, console output
  • Debug Mode — Playwright Inspector with breakpoints and locator highlighting
  • UI Mode — Interactive runner with time-travel and watch mode

Trace Capture Strategy

trace: 'on-first-retry'

Traces are captured only when a test fails and retries. This avoids wasting disk space (1-5 MB per trace) on passing tests while providing full diagnostics when needed.

screenshot: 'only-on-failure'

Automatic screenshot the moment a test fails. Immediate visual evidence.

Reporting

Three Reporter Strategy

List Reporter

Real-time console output during test execution. Shows pass/fail as each test completes. Best for local development.

  PASS auth > Register
  PASS auth > Login
  FAIL cart > Remove

HTML Reporter

Interactive web report with filtering, screenshots, and trace viewer integration. Ideal for presentations and stakeholders.

npm run report

JSON Reporter

Machine-readable output at reports/results.json. Parseable by CI/CD tools, Jenkins, GitHub Actions, or custom dashboards.

Engineering Decisions

Key Architecture Decisions

DecisionReasoning
Playwright over SeleniumAuto-wait, built-in assertions, trace viewer, no driver management
TypeScript over JavaScriptCompile-time errors, IDE intelligence, self-documenting interfaces
Class-based POM with inheritanceShared base methods, protected page access, single locator source
Fixture-level ad blockingDeterministic behavior, faster tests, no per-test setup needed
JSON for test data (not CSV/Excel)Supports nested data, native TypeScript support, git-diffable
Unique emails via Date.now()Test isolation, parallel safety, no pre-existing data dependency
Trace on first retry onlyFull diagnostics when needed, no disk waste on passing tests
Visual tests on Chromium onlyConsistent baselines; cross-browser handled by functional tests
